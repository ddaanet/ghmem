# ghmem — reified institutional memory for micro

ghmem turns micro's GitHub history into maintained design documents.
Recurring debates — option-count aversion, clipboard behavior,
highlighter architecture, wrap semantics — get re-litigated in issues
because the outcome of every past debate lives only in a closed thread
nobody re-reads. ghmem fetches that history into a local corpus, has
agents route each item to a topic, and synthesizes one living document
per topic under `docs/design/`: published on GitHub now, offerable
upstream later, and kept incrementally updated.

This document is the index: what the system must do, what it
deliberately does not do, what is still unsettled, and how the pieces
fit. It names its detail, each read on the question that sends a
reader there — command contracts in `docs/ghmem-harness.md`, the
argument behind each mechanism in `docs/ghmem-decisions.md`, refused
designs in `docs/ghmem-rejected.md`. That is the index-plus-detail
shape the topic docs use, for the reason §Design decisions gives under
**Doc form: hybrid, native-memory shaped**.

Its own change history is indexed in `docs/ghmem-changelog.md`.

## Functional requirements

**FR1 — the corpus holds the whole decision record.** `ghmem sync`
fetches every issue, pull request (body, comments, review threads,
review comments, merge metadata, diff), discussion, and the master
commit log into a local store. Scale, read off `corpus/cache.sqlite`
on 2026-09-03: 2,575 issues (866 open), 1,302 PRs (899 merged, 237
closed unmerged), 3,529 commits spanning 2016-03 to 2026-07, and 245
discussions. Those figures grow with every `sync` and are here for order
of magnitude; the corpus is the live source, and every other corpus
count in this document carries the date it was measured. Every signal
the pipeline needs is retrievable — closed-PR review threads (verified
on wrapindent PR #3107), issue↔PR cross-references via the timeline
API, reactions, and date-qualified search for incremental cursors.
Rationale: **PR diffs are corpus data** (`docs/ghmem-decisions.md`).

**FR2 — agents read the corpus, never GitHub.** `show`, `discussion`,
`heat`, `status` and `topic` render from the local store, and an
agent's whole procedure is written against them. Nothing hands a
spawned agent a credential of its own. That it issues no API call is a
property of its prompt, not of the containment hook — see
Limitations. Rationale: **12-factor split**
(`docs/ghmem-decisions.md`).

**FR3 — triage assigns each item it serves a verdict.** A verdict is a
topic name plus a routing note — one or two sentences naming the
decision signal seen, who decided what on what grounds — or the
reserved verdict `no-signal`, which also carries a note. A topic
verdict's note reappears in the item index `ghmem topic` emits. A
`no-signal` note appears in no rendered output at all, since
`routed_items` excludes `no-signal`; it lives on its ledger event and
its `Route` row. Coverage of the whole corpus is FR9's end state, not
a property that holds today: 95 of the corpus's 3,877 issues and PRs
carry a verdict as of 2026-09-03. Rationale: **A note is prose, so it
travels on stdin alone**, **Only about a third of closed PRs cleanly
encode a design decision** (`docs/ghmem-decisions.md`).

**FR4 — synthesis writes one living document per topic.** Each
`docs/design/<topic>.md` carries YAML frontmatter with a `description:`
hook line and the body structure Architecture §2 defines.
`docs/design/INDEX.md` is regenerated by `ghmem index` from those docs.
The synthesize agent is told not to edit it, which is a prompt rule
and not a hook guarantee — see Limitations. Rationale: **Doc form:
hybrid, native-memory shaped**, **Topic-doc structure**
(`docs/ghmem-decisions.md`).

**FR5 — every requirement in a topic doc is citation-backed.** FRs,
NFRs and limitations cite the issues, PRs or commits behind them; a
requirement with no citable maintainer behavior does not get written.
It is the standing rule against hallucinated rationale, held up by the
synthesize agent's prompt and by review rather than by the harness.

**FR6 — the pipeline is incremental.** The same `ghmem sync` is the
update path: it fetches only the delta past its cursor. Routing marks
topics dirty, and a run re-synthesizes the dirty set alone. Rationale:
**Incremental synthesis reloads full topic context**
(`docs/ghmem-decisions.md`); refused: **Delta machinery for incremental
synthesis** (`docs/ghmem-rejected.md`).

**FR7 — a verdict is correctable, and a stranded dispatch is
reclaimable.** Three mechanisms correct a verdict. Re-routing
supersedes one with a better verdict; `ghmem unroute` withdraws one
reached wrongly, returning the item to the queue; `ghmem rebuild`
appends a `reenter` event for every item whose GitHub thread has moved
past its recorded verdict, so the next cycle re-judges it. `ghmem
requeue` is not a verdict correction — it frees items a crashed
session dispatched but never routed. A correction that leaves a topic
with no route naming it deletes that topic's `Topic` row, whichever
mechanism reached it. Rationale: **Freshness is stamped on the
route**, **Emptying a topic deletes its `Topic` row**
(`docs/ghmem-decisions.md`); refused: **Refusing to unroute a
`no-signal` verdict**, **Relaxing `record_verdict` to accept a live
re-route** (`docs/ghmem-rejected.md`).

**FR8 — contributor standing is rendered, never inferred.** Every
author in every rendered output carries the standing they held at
posting time, derived from the corpus. Rationale: **Contributor
standing is computed, time-varying data**, **`author_association` is a
hint, never authority** (`docs/ghmem-decisions.md`); refused: **GH
Archive for historical `author_association`**
(`docs/ghmem-rejected.md`).

**FR9 — backfill covers the whole corpus in heat order.** Hottest
topics get their docs first and the cold tail is triaged last.
Skeleton-first is the schedule; full coverage is the end state.
Rationale: **Heat-ranked backfill order** (`docs/ghmem-decisions.md`).

## Non-functional requirements

**NFR1 — fetching stays inside GitHub's rate limits.** Full per-item
REST enrichment would be ~7–10k calls against a 5k/hr core limit, so
bulk fetch is GraphQL with nested comment/review/timeline batching.
PR diff text is not exposed via GraphQL, so `sync` takes it from the
REST diff endpoint — ~1 call per PR, ~1.3k total, well inside the
budget. The search endpoint (30/min) serves incremental cursors only,
never enumeration.

**NFR2 — all deterministic work lives in the harness.** Fetch, store,
render, rank, meter and ledger are CLI concerns. Agents only judge:
route items to topics, and write prose. Rationale: **12-factor split**
(`docs/ghmem-decisions.md`).

**NFR3 — the agents' command surface is mechanically contained.** A
PreToolUse allowlist hook on each agent definition admits only `ghmem`
invocations, with no chaining, substitution, pipes or redirects, and
denies every other command with a structured reason — so what an agent
may *run* does not rest on it following its prompt. The hook reads
command shape, so which `ghmem` subcommand runs is outside what it
decides. Rationale: **The allowlist is a positive character class over
the whole command string** (`docs/ghmem-decisions.md`); refused: **A
deny-pattern hook**, **Blocking `ghmem unroute` in the containment
hook** (`docs/ghmem-rejected.md`).

**NFR4 — the CLI meters the batch; a model never counts.** Budget
constants are the CLI's configuration, not orchestrator input, and are
enforced CLI-side against ledger events. The agent loops until the CLI
says the batch or the queue is done. Rationale: **Triage agents pull
their own items; the CLI meters the batch**, **A diff body is the only
cuttable part of a packet** (`docs/ghmem-decisions.md`).

**NFR5 — the ledgers are append-only and the routing ledger is
committed.** Nothing is edited out: a correction is another append.
`routing.jsonl` is the system's own memory and the one corpus file a
re-sync cannot regenerate.

**NFR6 — backfill fits a Max5 subscription.** The whole corpus is
~3–4M tokens of raw text; one-pass Sonnet triage ≈ 5M input tokens and
Opus synthesis ≈ 3–6M more, which fits across a few 5-hour windows.
Refused: **Digest-only tiers in the synthesis context**
(`docs/ghmem-rejected.md`).

**NFR7 — heuristic constants are grounded in data, never hip-shot.**
Each weight and threshold ships provisional and stays provisional
until an analysis over the real corpus is recorded against it. One
family has had that analysis: the heat weights, calibrated 2026-07-25
against 198 labels and **retained**, because no fitted vector ranked
better and the fitted one lost under cross-validation
(`docs/ghmem-heat-weights.md`). Three families have not; they are
listed in Open questions. Rationale: **Calibration normalizes before
it weights** (`docs/ghmem-decisions.md`).

**NFR8 — the toolchain gate is the bar for every change.** `just
green` runs ruff with `select = ["ALL"]` and a curated ignore list,
mypy strict with `extra_checks`, docformatter, pytest (+pytest-mock)
and the bats hook suites; a change lands only when it passes. The
settled choices under it: a uv-managed project, a click CLI,
**githubkit** for GitHub access (typed, active, built-in retry) with
the token from `gh auth token` or `$GITHUB_TOKEN`, and a Python floor
of **>=3.14** — its type-annotation improvements make stringified
forward references unneeded and undesirable, and this is developer
tooling with no backward compatibility owed. Refused: **Shelling out
to `gh api graphql`** (`docs/ghmem-rejected.md`).

**NFR9 — 400 lines is the reader-context budget for a human-reviewed
artifact**, plans and PRs alike. A budget, not a hard cap: a split has
its own cost — re-reading several documents, chasing cross-references
— so a cohesive document may run over when the split would cost its
reader more than the length does, provided the overage is stated
rather than absorbed. A PR that merely reorganizes code with no
behavioral change is exempt outright. This document holds to the
budget as an index and names its detail: the command contracts in
`docs/ghmem-harness.md`, the argument behind each mechanism in
`docs/ghmem-decisions.md`, the refused designs in
`docs/ghmem-rejected.md`. Separating a decision from the requirement it
justifies risks the two drifting apart, so the reference runs one way
and always resolves: a requirement names the decision behind it by
section title, no decision restates the requirement it serves, and
there is one copy of each to change.

**NFR10 — the pipeline is validated against ground truth before it is
trusted.** It runs on the wrapindent cluster (#3107, #2374 and their
cross-references) and the produced topic doc is compared against
`docs/softwrapcolumn-vs-wrapindent.md`, which was validated by hand.
The comparison is purely **semantic** — freshly generated output has
no reason to be structurally similar to a hand-written doc, so a
textual diff is useless; the gate judges whether each required signal
is present and citation-backed. Missing the option-count aversion, the
indent-vs-wrap axis distinction, or the stall rationale means the
prompts are not ready. Triage validation runs against **distractors**
— a mixed queue of ~15–20 items around the cluster, cross-references
plus contemporaneous unrelated bug reports and support questions,
where most items should come back no-signal or other-topic — because
routing only the wrapindent cluster against an empty topic list would
make the match trivial and prove nothing about accuracy.
Harness-level, `sync` resumability and cursor correctness are testable
against recorded fixtures, and `heat`/`triage`/`route`/`status` are
pure functions over the local store, testable without network. **This
gate has not run**, so the requirement stands unmet; see Open
questions.

## Limitations

Accepted trade-offs and known constraints of the current design.

- **No hosted service, no embeddings or RAG index, no chatbot.**
- **No mining of Discord, Gitter or mailing lists** — that design
  chatter is unretrievable, and it is an accepted blind spot rather
  than a gap to close.
- **GitHub Projects data needs a `read:project` token scope** and is
  skipped; the wiki would need a separate `.wiki.git` clone to check
  and is presumed unused.
- **No automatic upstream PR of the docs.** Upstreaming is a later,
  manual decision.
- **Topic docs are not exhaustive changelogs.** They record decisions
  and debates, not history for its own sake.
- **Containment is command-shape, not subcommand.** `ghmem-only.sh`
  admits any `ghmem` invocation, `sync` and the corpus-wide mutating
  operator commands included. The cost was chosen knowingly: deciding
  which subcommands a caller may run needs authority vocabulary the
  hook does not have — it sees one command string, and one copy of it
  contains both agents (see **Blocking `ghmem unroute` in the
  containment hook**, `docs/ghmem-rejected.md`).
- **`INDEX.md` is protected by prompt, not by hook.**
  `scope-docs-design.sh` scopes the synthesize agent's writes to
  `docs/design/`, which *contains* `INDEX.md`, so a write to it would
  pass. The agent definition forbids it instead, and a bad write is
  repaired by re-running `ghmem index`.
- **A routing note is a single line.** `route` rejects an empty or
  multi-line note, so a note is one or two sentences by construction.
- **A `no-signal` note is never rendered.** It is recorded and
  reviewable in the ledger and the routing mirror, but no command
  displays it, so the judgement it holds is not visible in any
  assembled context.

## Open questions

Live and unresolved; recorded here so that no branch settles one
quietly.

- **NFR10's ground-truth gate has not run.** No wrap topic doc exists
  under `docs/design/` and the changelog records no validation slice,
  while 95 items are routed and five topic docs are synthesized. The
  prompts carry no evidence of accuracy beyond their outputs reading
  well. Either the gate runs, or NFR10 is rewritten to say what is
  actually relied on.
- **Three constant families are still provisional** (NFR7): the
  standing thresholds (`OWNER_LOGIN`, `MERGE_THRESHOLD`,
  `ACCEPTED_PR_THRESHOLD`), the batch budget (`BATCH_ITEMS = 12`,
  `BATCH_CHARS = 200_000`) and the diff valve
  (`DIFF_BODY_MAX_CHARS = 25_000`). Each still carries `PROVISIONAL`
  in the source, and the pipeline's behaviour depends on all three.
- **The `topic merge` event.** A topic-name-to-canonical mapping,
  appended to the routing ledger and replayed by `rebuild`, is the
  next lever on the singleton problem — 57 of 71 topics hold exactly
  one item (2026-09-03). Serving the topic list in every triage packet
  narrows the problem going forward but cannot close it: it does not
  re-judge names already minted. Its semantics (what happens to the
  merged name's doc, whether a merge is itself withdrawable) are
  unsettled.
- **The triage rubric's no-signal rate.** 4 of 95 routes came back
  `no-signal` against a 36.5% base rate measured on the corpus, so
  either the rubric has drifted toward routing everything or the
  routed sample is unrepresentative. It is a judgement about prompt
  content, independent of the mechanics around it.

## Architecture

### 1. Harness — `tools/ghmem`

Python/uv, click, githubkit, SQLAlchemy/SQLite. No agent ever calls
the GitHub API; agents read what `ghmem` commands emit from the local
corpus.

Each command's contract — what it emits, accepts and records — is in
§Commands of `docs/ghmem-harness.md`, with the ledger and cache layout
under **Storage** there.

### 2. Artifact — `docs/design/`

- `INDEX.md` — the recall surface, **autogenerated** by `ghmem index`
  from the topic docs' frontmatter, alphabetical by topic.
- `<topic>.md` (flat, beside INDEX.md) — per-theme living documents.
  YAML frontmatter carries `description:`, the hook-style index line
  for this topic. The body has a fixed section structure: **FR / NFR /
  Limitations / Open questions / History**.
  - FRs and NFRs are *descriptive*, not aspirational: requirements the
    project has demonstrably enforced, extracted from maintainer
    statements and merge/reject behavior (clipboard FR "must work over
    ssh without X forwarding (#93)"; project-wide NFR "option-count
    parsimony (#2374, #3107)"). Numbered for stable citation
    (`softwrap.NFR2`) from INDEX.md and future sessions.
  - **Limitations**: accepted trade-offs and known constraints of the
    current design — what it deliberately does not do and the cost the
    project chose to live with. NOT a graveyard of rejected
    approaches: a rejection that encodes a norm becomes an NFR, and
    the debate record for a rejected or stalled approach lives in
    History.
  - **Open questions**: live, unresolved debates and their current
    front line — who holds what position, where it stalled. Keeps the
    most re-litigation-prone material out of History.
  - **History**: compressed chronological debate digest that the other
    sections cite into. Rejected and stalled approaches are recorded
    here with their rejection rationale; rejected and stalled PRs are
    first-class evidence.
  - Norm topics — cross-cutting philosophy like options parsimony —
    are legitimately all-NFR. Empty sections are allowed, and the
    synthesis prompt must not invent filler to populate them.

Rationale: **Doc form: hybrid, native-memory shaped**, **Naming:
`docs/design/`, flat, "topic doc"**, **Topic-doc structure**
(`docs/ghmem-decisions.md`); refused: **Heat-ordered `INDEX.md`**
(`docs/ghmem-rejected.md`).

### 3. Agentic layer — two custom agents

Both are `.claude/agents/` definitions with pinned models, their full
procedure text inline in the definition body, and a frontmatter
PreToolUse allowlist hook.

- **ghmem-triage (Sonnet).** Input: none — no item content, no budget
  numbers; it opens its own session and rides the `triage`/`route`
  loop until the CLI ends it. Its final report leads with the terminal
  status — `batch complete` (items remain: spawn another batch) or
  `triage complete` (stop) — then the id → verdict lines, so the
  orchestrator branches on the first line. It may propose new topics,
  consulting the packet's own `topics:` line first to avoid
  near-duplicates. "No-signal" is a comfortable default verdict, not a
  failure: most items encode no decision.
- **ghmem-synthesize (Opus).** Input: one topic's context from `ghmem
  topic`, with its snapshot token. Output: create or update that topic
  doc — including its frontmatter `description:` hook line — then
  `ghmem close <token>`; the harness regenerates INDEX.md. A stale
  token, meaning activity landed mid-synthesis, is a normal race
  rather than an error to escalate: the same agent re-assembles from
  the fresh snapshot, rewrites the doc and retries, stopping only
  after two consecutive stale tokens. Its prompt carries FR5's
  citation rule with teeth — user chorus is demand evidence, never
  policy — and requires History and Open-questions entries to
  attribute positions by standing, since a live debate's front line is
  where people with merge power currently stand.
- **The incremental loop** is `ghmem sync` → `ghmem rebuild` → `ghmem
  requeue` → triage the delta → synthesize dirty topics. It is fully
  deterministic — agents report terminal status lines precisely so the
  orchestrator needs no judgment — so orchestration can be a
  skill-driven session now and an Agent-SDK script later, running on
  subscription auth and removing the orchestrator model from the loop.
  Scripting it is the natural endgame, not a prerequisite.

Rationale: **Model tiering**, **Triage and synthesize are custom
agents, not a skill and a prompt**, **One topic per synthesis spawn, no
batching** (`docs/ghmem-decisions.md`); refused: **A companion
procedure skill for the agents** (`docs/ghmem-rejected.md`).

### 4. Failure handling

- Rate-limit exhaustion mid-sync: persist the cursor, exit with a
  resume hint, never lose fetched data.
- GraphQL partial failures (a single bad node): log, skip, record the
  id in the fetch ledger as fetch-failed for retry.
- Token scope gaps (Projects): detect, warn once, skip.

The routing-side failures are answered by the commands above rather
than by separate machinery: triage disagreement by re-routing or
`unroute` (latest verdict wins, always an append), a close-out race by
`close`'s digest compare-and-set, and a stranded dispatch by `status`
plus `requeue` at run start — explicit reclaim instead of timeouts, so
a slow-but-live session is never raced (**Dispatch timeouts for crash
recovery**, `docs/ghmem-rejected.md`).
